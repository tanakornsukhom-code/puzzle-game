# เหมียวป่วนคาเฟ่ — Chaotic Pet Café

เกม Tricky Puzzle ภาษาไทยบนเว็บเบราว์เซอร์ ออกแบบสำหรับจอมือถือแนวตั้ง ผู้เล่นเป็นบาริสต้าที่ต้องแก้ออเดอร์กวน ๆ ด้วยการใช้สิ่งของและฉากในร้าน

## ระบบทำอะไรได้บ้าง

- เล่นปริศนา 30 ด่าน พร้อมเลือกด่าน เริ่มใหม่ และข้อความตอบสนองเมื่อทดลองใช้ของ
- ลากวาง หรือแตะเลือกของแล้วแตะเป้าหมาย รองรับ Tab / Enter ผ่านปุ่มในหน้าเว็บ
- สำรวจฉากด้วยภาพสถานะจริง: เปิด–ปิดบานหน้าต่าง รูดม่าน เปิดกรอบรูป ยกเบาะ เปิดตู้ ฝาพื้น และสวิตช์ไฟ; ของที่ตรวจแล้วปิดกลับได้โดยไม่ให้รางวัลซ้ำ
- ปริศนาหลายขั้นมี prerequisite; ผ่านขั้นแล้วเปลี่ยนสิ่งของ ข้อความ และสถานะฉาก
- รูดหรือกดค้าง 3 วินาทีได้ และมีทางเลือกแตะสองครั้ง
- คำใบ้ 3 ระดับตามขั้นปัจจุบัน พร้อมเปิด/ปิดเสียงสังเคราะห์ด้วย Web Audio
- บันทึกด่านที่ผ่านและการตั้งค่าเสียงใน localStorage ของเบราว์เซอร์ พร้อมย้ายความคืบหน้าจากเวอร์ชัน 15 ด่านเดิม
- ใช้ภาพฉากและไอเทมที่เจนขึ้น ไอเทม 44 แบบเป็น PNG โปร่งใสแยกชิ้น

ยังไม่มีระบบบัญชี เซิร์ฟเวอร์เก็บคะแนน โฆษณา เซนเซอร์เขย่า หรือการซิงก์ความคืบหน้าข้ามอุปกรณ์ การล้างข้อมูลเว็บไซต์อาจลบความคืบหน้าได้

## เริ่มเล่น

เปิด `index.html` ด้วยเบราว์เซอร์ได้โดยตรง หรือใช้ Node.js เปิด local server:

```powershell
cd 'E:\puzzle game'
node server.cjs
```

เปิด http://localhost:4173 บนคอมพิวเตอร์ หรือ `http://<IP ของคอมพิวเตอร์>:4173` บนมือถือที่อยู่เครือข่ายเดียวกันและเครือข่ายอนุญาต กด Ctrl+C เพื่อหยุดเซิร์ฟเวอร์

ไม่ต้องรัน npm install หรือ build ตัวเกมใช้ HTML, CSS และ JavaScript โดยตรง ฟอนต์โหลดจาก Google Fonts และมีฟอนต์ระบบสำรอง `server.cjs` เป็นเซิร์ฟเวอร์สำหรับพัฒนาในเครื่อง

## ลำดับการทำงานของระบบ

1. `index.html` โหลด CSS และ `game.js`
2. เกมอ่านความคืบหน้า เตรียมข้อมูลด่าน และโหลดด่านแรก
3. `load()` สร้างไอเทมกับส่วนของฉากที่โต้ตอบได้ แล้วคืนสถานะเริ่มต้น
4. Pointer Events หรือ click จากคีย์บอร์ดส่งต่อไป `tap()`, `release()` และ `interact()`
5. `advance()` ตรวจ prerequisite ของด่านหลายขั้น ก่อนสร้าง/นำวัตถุออกและปรับสถานะฉาก
6. `win()` บันทึก progress และแสดงผลสำเร็จ; การเปลี่ยนด่านจะยกเลิก timer เดิม

ข้อมูลด่านอยู่ใน `levels`, `lessons` และรายการที่เพิ่มผ่าน `levels.push()` ใน `game.js` ชื่อชนิดไอเทมต้องตรงกับ `spriteKeys` และมีไฟล์ภาพจริง ส่วนของฉากต้องมีชื่อและพิกัดใน `sceneryNames` / `sceneryLayout`

## เส้นความยาก

| ด่าน | เป้าหมาย |
|---|---|
| 1–5 | เข้าใจตรรกะกวน ลากวัตถุและเปิดของซ่อน |
| 6–10 | เรียนรู้การสำรวจฉากและการรูด ผ่านโจทย์สั้น |
| 11–20 | ผสมหลายขั้นในบริบทผี สวน ไอที วันเกิด และดนตรี |
| 21–30 | ใช้ฉากร่วมกับสิ่งของ สอนกดค้าง และจบด้วยปริศนารวม |

ดูรายละเอียดและแหล่งอ้างอิงใน `LEVEL-DESIGN.md` จำนวนขั้นไม่ใช่ผลวัด Flow; ยังต้องทดสอบความยากกับผู้เล่นจริง

## ทดสอบ

รันจากโฟลเดอร์โปรเจกต์:

```powershell
node --check game.js
node check.cjs
```

ผลตรวจรอบล่าสุดผ่าน 30 solution paths และ focused regression tests รวมถึง Tester ตรวจ click listener แบบคีย์บอร์ดครบ 30 ด่านโดยอิสระ ทั้งหมดเป็น **DOM/event simulation** ไม่ใช่การยืนยันภาพที่ render จริง ความลื่น หรือสัมผัสบนมือถือจริง ดูสถานะที่ยัง Pending ใน `QA-REPORT.md`

## ขั้นตอนพัฒนาต่อ

Dev แก้โค้ด → Tester ส่ง request พร้อมวิธีทำซ้ำและเกณฑ์ผ่าน → Dev/Optimizer แก้ตามเจ้าของไฟล์ → Tester ตรวจซ้ำ → รวมและส่งมอบเฉพาะเวอร์ชันที่ผ่าน checks อ่าน `WORKFLOW.md` ก่อนแก้เกมครั้งถัดไป

## Scene graph: แยกทุกอย่างเป็น Object
ไฟล์ scene-layout.js เป็นศูนย์กลางตำแหน่ง ขนาด สถานะ และเลเยอร์; game.js สร้างวัตถุฉากใน #roomObjects แยกจากไอเทมปริศนา พื้นหลัง assets/room-shell-v6.png มีแค่ผนังกับพื้น เฟอร์นิเจอร์/ชิบะ/ประตู/โคมไฟ/ต้นไม้/เคาน์เตอร์ใช้ PNG แยก assets/scene/ ดู SCENE-OBJECTS.md สำหรับรายการทุก ID และวิธีแก้ตำแหน่ง
